# OpenCode MCP specification

## Product and compatibility

`@nones/opencode-mcp` is a local MCP server, Node CLI, and typed TypeScript SDK for an already running OpenCode 2 server. Initial support targets the real OpenCode 2.4.1 HTTP API. Codex and other MCP clients use stdio. The CLI includes `mcp`, `doctor`, `start`, `send`, `status`, `messages`, `sessions`, `monitor` (alias `watch`), `run`, and `help`, plus the equivalent `oc2-mcp` bin alias. The transport targets one configured OpenCode instance. It never creates an implicit private OpenCode server. Use the current stable `@opencode/client` for managed discovery and current stable MCP SDK v2, Zod, TypeScript and GitHub Actions, with versions established from published releases. Follow the `kaiten-mcp` separation of API client, domain services, tool registration, runtime configuration, CLI, SDK exports and package CI. Bun 1.4.5 is the pinned workspace build and test runner; native `bun fmt` formats and `oxlint` lints. The packaged CLI runs with Node 22.14+ and has no Bun runtime dependency.

## CLI contract

The CLI is built on Commander.js 15.1.0 with asynchronous handlers. `mcp` and `doctor` are ordinary commands. When the user supplies no arguments, the entrypoint parses `["mcp"]` so the default launch runs the same stdio server. Built-in `help`, `--help`, `-h`, `--version`, and `-V` work without an OpenCode connection. Command help shows descriptions plus copyable examples. The version comes from statically imported package.json metadata bundled by Bun, so the CLI and MCP serverInfo report 0.4.0 under Node. Unknown commands and options exit nonzero with the invalid token on stderr and do not connect. Runtime connection errors stay on stderr. `doctor` prints indented JSON to stdout, while `mcp` reserves stdout for JSON-RPC.

Session commands use the running service and native `ses_...` IDs as their only handles; there is no local job store, SQLite, Python dependency, or generated monitor. `start -C <dir> -f <file|->` validates the prompt and working directory, resolves the model from `--model`, `OPENCODE_MCP_MODEL`, legacy `OC2_MODEL`, then `opencode-go/deepseek-v4.1-flash`, validates the model and optional `#variant` against native `model.list`, creates the session, and submits with `delivery: steer`. It prints the session ID and native admission receipt and returns without waiting. Invalid models and unsupported variants fail without fallback. If creation succeeds and submission fails, diagnostics keep the session ID. `send <sessionID> -f <file|-> [--delivery steer|queue]` submits immediately to the same owning session, defaults to steer, prints the receipt, never creates a session, and does not wait. Both read stdin for `-`.

`status` prints current native metadata. `messages` prints the latest native messages with the upstream cursor and supports `--limit` and `--cursor`. `sessions` discovers native IDs with a bounded default limit. `monitor`/`watch` emits newline-delimited JSON with initial status, filtered native events, and normalized turn-start, steer-delivered, tool-completed, idle, success, failure, and timeout events, including the session ID and available message IDs. It supports `--until-turn` and `--timeout`; without `--until-turn` it follows successive turns. Exit codes are 0 for a successful observed turn, 2 for failed or interrupted only in until-turn mode, 124 for timeout, 130 for signal, and 1 for validation, connection, or protocol failure. `Ctrl+C` stops observation without interrupting the session. `run` composes start and until-turn monitoring with the same input/options and `--timeout`, prints the started line promptly, and uses the created session metadata as the pre-prompt baseline.

The package installs `oc2-mcp` as a second bin name pointing at the same `dist/cli.js`.

## Connection and scope

With no endpoint override, discover the authenticated managed service through the official `@opencode/client/service` discovery and header adapter in process. Prove this path on the installed OpenCode. If SDK discovery requires a non-default registration file, accept `OPENCODE_MCP_SERVICE_FILE` as an opaque path passed to the SDK. With `OPENCODE_MCP_URL`, authenticate with a password passed in the process environment via `OPENCODE_MCP_PASSWORD` (Basic user `opencode`). Keep URL credentials, headers, authentication material and raw upstream errors out of stdout, diagnostics and tool results. Explicit HTTP endpoints default to loopback, remote access requires an explicit opt-in and HTTPS. Honor timeouts and MCP cancellation, disable following redirects, and never start, restart or replace the user's OpenCode service automatically. All projects and chats on the attached server are visible by default. An optional `OPENCODE_MCP_ALLOWED_DIRS` constrains project/session scope by canonical directory boundaries. When configured, endpoints with unknown or unverifiable workspace scope fail closed. Native `model.list` is admitted in scoped mode only when `query.location.directory` is explicitly present and canonicalizes inside the allowlist; unrestricted model discovery stays denied. Outside scoped mode, an empty project-scoped catalogue for a fresh directory falls back to the global native catalogue for model and variant validation. CLI doctor reports endpoint and capability health without credentials.

## MCP contract

Register discoverable tools with input schemas, structured result content, and accurate read-only/destructive annotations. Keep tool calls bounded by timeout, page count, and response size. Preserve upstream cursors and IDs. Provide explicit errors for unsupported operations, missing sessions, wrong ownership, insufficient access, pending delivery and timeouts. A timed-out result never implies the mutation failed or is safe to retry.

| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Server and projects                   | Version/health, operation catalog, project list and details or lookup with high-fidelity metadata, location/workspaces, project configuration and supported updates                                                                                                                                                                                                                                                                                                                                                                          |

| Live steering                         | Native session prompt `delivery: steer` and `queue`. Return actual acceptance receipt and message/session ID without waiting for the result by default. In active sessions reuse the owning server, preserve model/agent unless explicitly asked, and never recreate/fork one in response to a missing ID                                                                                                                                                                                                                                    |
| History                               | Native message list/get, cursor paging, and an explicit grouped history view. Each user message starts a group holding subsequent assistant steps, text, tool call identifiers, status, output and error, and terminal marker when present. Multiple user prompts separated by steer remain separate groups within the same execution until idle. Expose message IDs and indicate boundaries/truncation where a page begins or ends mid-group. Use upstream session log/turn routes where supported, otherwise group ordered native messages |

| Subagents                             | List child sessions by parent ID, get details and history, prompt/steer/interrupt an existing child, optionally start a real child via native parent session creation if the installed API supports it. Do not emulate native parent linkage                                                                                                                                                                                                                                                                                                 |
| Skills/plugins and related management | List and get installed skills and plugins in location context, activate a skill for a session, plugin update/check and registry operations where supported by installed API, and expose native permission/form inspect/respond, jobs and supported updates through the operation layer                                                                                                                                                                                                                                                       |

Supplement ergonomic tools with `opencode_operations` and `opencode_request`, using the connected server's `GET /openapi.json` catalog and exact operation IDs, method, supported path/query/body. Build paths by encoding individual params and pin requests to the configured origin. Reject absolute URLs, dot segments/traversal and uncontrolled headers. Classify operations conservatively. Never route credential/token/pair/auth-connect endpoints or emit secret/token/password/auth fields. Generic access must not bypass scope or mutation controls. SSE routes use the event tool. Raw upstream data is bounded. Default lifecycle writes such as prompt/create remain usable.

Native live SSE has no replay, so CLI monitoring uses short bounded reads (about one second) and reconciles with `session.get` on each cycle. Attach and cycle work share caller cancellation and a deadline signal so a blocked read cannot overshoot timeout or `Ctrl+C`. Consecutive stream and snapshot failures are counted separately and a short minimum cycle prevents a hot retry loop when the stream closes early. Completion comes from native `time.busy`, `time.idle`, and execution outcome, never from an admission receipt or a stale outcome. Until-turn mode returns after the observed turn; follow mode reports failures and keeps observing. Terminal normalized events are deduplicated.

## Environment policy

`OPENCODE_MCP_ALLOW_DESTRUCTIVE=1` plus per-call `confirm: true` enables deletions, irreversible rollback/commit, filesystem writes/deletes, and similarly destructive operations. `OPENCODE_MCP_ALLOW_ADMIN=1` plus confirmation enables server-global configuration and plugin install/update/remove and other cross-session administration. `OPENCODE_MCP_ALLOW_EXEC=1` plus confirmation enables explicit shell/PTY execution. Default for all three is off; invalid values never enable a capability. Apply centrally to all tool paths including generic operations. Other unclassified mutations require admin and confirmation. App-managed credential, pairing and authorization provisioning stays in OpenCode. No secret values in repo, package, process arguments or logs. Permission replies are scoped to the actual named session/request. Document operational tradeoffs and list flags/operations in README.
